# ToviCam UI implementation and verification — 0.17

Updated 8 October 2026. The black-and-gold Native Views refactor is implemented against the nine workspace PNG references and has completed the scoped emulator verification documented in reports/ui_redesign_20261007/README.md. Physical capture and real store QA remain outstanding.

ToviTheme supplies #0B0B0C surfaces, #171719 cards, #FFC629 emphasis, #F5F5F5 text and #A5A5AC secondary text. PageTopBar, camera artwork cards and rounded actions share these tokens. The public brand is ToviCam; the store title remains ToviCam: Retro Digital Camera. Existing stored style identifiers, package IDs and Pictures/PhyToy storage remain unchanged.

## Flows

- Camera: the current style capsule opens its detail page; flash/settings sit alongside it. The bottom rail uses independent camera artwork, a gold selected border and lock badges, with a white shutter and gold ring, recent-photo thumbnail and lens switch. Tap EV/zoom pills to adjust supported hardware values or reset; tap-focus, grid and pinch remain. Exposure draws vertically when space/font size permit and horizontally in compact conditions. Quick zoom values are hardware bounded; intermediate zoom does not highlight an unrelated preset. During capture the existing stable control snapshot and disabled conflicting actions remain in force.
- Camera lifecycle: the prior shared single-worker queue, generation/resource identity checks and Texture retirement behavior are retained. This UI refactor does not change camera startup/shutdown, Camera2/3A control, capture parameter snapshots, crop/rotation/mirroring, image encoding, EXIF, MediaStore/indexing, billing authorization or engine/profile/shader algorithms. MainActivity changes in this refactor bind presentation navigation, including gallery settings and review position.
- Style rail: free cameras shoot immediately. Locked cameras enter free live trials directly; the detail capsule, explicit Unlock or locked shutter opens the style-detail template. Trial persistence and purchase authorization keep their existing rules. Entry triggers neither capture nor checkout.
- Purchase: six cameras share a large artwork/description template and matching original/processed example cards. The separate decision viewport contains full-width preview/unlock buttons; wide landscape uses a scrolling side rail, while other windows cap the dock to reserve a scrolling details viewport. Store-supplied prices and loading/unavailable/busy/pending/owned states retain distinct rendering. Owned styles offer Use this camera. Restore/retry and channel scope remain available in the details pane. Examples use the existing artificial scene and shipped reference profiles; camera artwork is decorative and never an engine input. No fallback price is fabricated.
- Gallery: newest-first app photos are grouped by local capture date in virtualized rows with 2–6 adaptive columns, rounded thumbnails and compact style badges. Unknown dates use Saved photos. Existing bounded background scans, thumbnail workers and cache remain; visible-row selection avoids copying all remaining rows. Return preserves the scroll anchor, including a surviving neighbor when its first photo was deleted. Loading/empty/retry and Take your first photo remain; Camera/Gallery/Settings tabs are wired, and closing settings opened here returns to the gallery. No selection/multi-delete feature is invented.
- Review: a real navigation position, style/time/dimensions card, Share/Delete/Info and primary Continue shooting accompany a photo initially fit without cropping. Pinch/double-tap zoom stays bounded to 4×; accessible zoom/reset and explicit previous/next remain. A horizontal release of at least 56 dp, dominant over vertical displacement, navigates only at fit scale and after no multi-touch/double-tap in the gesture; enlarged photos pan. Info uses saved style, actual dimensions/pixel count/aspect, filename and capture time derived from the existing filename; absent ISO/aperture are omitted. Delete still confirms before the existing provider/system-consent path; sharing still grants read access only to the selected content URI. Loading/error/retry remain and fit a scrolling state viewport.
- Settings: Shooting / Experience / App use grouped dark cards, gold icons/switches, short hints, wrapping values, separate detailed help, persistent purchase/restore results and reset confirmation. Actual preferences, entitlement labels and configured contact/privacy behavior retain their existing rules. No location, auto-rotate or save-destination toggle was added.

## Layout and accessibility

Controls define minimum 48 dp touch targets, accessible labels and state; reachable target geometry was measured in the scoped phone/large-font/compact runs. The final ordinary-font review exposes Share/Delete/Info without scrolling at 360×640dp, with each target at least 68dp tall. Text uses sp and wraps; purchase/settings scroll. Portrait uses a bottom camera rail; landscape and short windows use compact controls. Review separates navigation from Share/Delete/Info, scrolls information/tools while Continue remains fixed in ordinary portrait, and scrolls the whole action column in landscape or very short windows. Landscape width at least 480 dp places tools beside the image. Large-font actions stack in a narrow tool region. Loading/retry also scroll when vertical space is scarce. The first review gesture hint hides after three seconds or zooming and allows three lines at large font scale. Insets account for bars/cutouts. Preview/saved crop retains the selected aspect and orientation; initial review fits the image and enlarged pan remains bounded.

Background controls are removed from the accessibility tree while a modal page is shown. Pages use pane/window-change announcements and restore ordinary keyboard focus without forcing screen-reader focus. The photo exposes accessible zoom actions so gestures are not the only route. Camera/review state survives rotation, with decoding cancelled/restarted safely.
